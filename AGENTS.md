# Agent guide

This repository is **sdp**, and it is also specified *with* sdp. Two kinds of work happen here:
changing the tool (TypeScript in `src/`) and changing its specifications (Markdown in `specs/` and
`docs/`). Both go through the same loop.

## Find things

- Any node by id: `grep -rn "REQ-graph-query" specs docs src` — ids are literal everywhere.
- Code linked to the graph: `grep -rn "@sdp" src/`.
- Graph questions: `node src/cli/main.ts q '<pattern>'` (syntax: `docs/DESIGN.md` §6, or `sdp q --help`).
- Everything about one node before you change it: `node src/cli/main.ts context <id>`.
- The architecture that matters (and only that): `node src/cli/main.ts arch`.

## Change behaviour

1. Find or create the spec (`node src/cli/main.ts new requirement "…"`). Write or adjust scenarios
   first; they are the acceptance tests.
2. `node src/cli/main.ts run <spec-id> --snippets` shows undefined steps with suggested definitions.
   Step definitions live in `specs/steps/*.steps.ts` and drive the real pipeline against an
   in-memory workspace (`loadMemoryProject`). Prefer extending existing steps over adding near-duplicates.
3. Implement in `src/`. Unit tests in `test/` cover parsing, query, checks and the runner.
4. `npm run verify` must pass: typecheck, unit tests, `sdp run` (no failures outside gates), `sdp check` (no errors).

## Conventions

- Node.js 24 runs `.ts` directly: use erasable syntax only (no enums, namespaces, parameter
  properties), import with `.ts` extensions.
- Effect 4: `Effect.fn`/`Effect.gen` for IO workflows, `Schema` for external data, services at the
  edge (`FileSystem`, `Path`); keep parsing/graph/query/check pure. Effect docs ship in
  `node_modules/effect/AGENTS.md` — use those, not memory of Effect 2/3.
- Relations and kinds are free-form; do not add code that depends on a closed vocabulary.
- Architectural significance is the architects' call: do not mark or unmark `significant` on your
  own initiative; propose it instead (`sdp arch --candidates` lists suggestions).
- While the project is in inception, a decision that changes is rewritten or deleted, not
  superseded — keep the graph free of history noise; git keeps the history.
- `.sdp/results.json` is generated by `sdp run`; do not edit it by hand.
